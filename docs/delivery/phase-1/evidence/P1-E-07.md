## Scope

This slice connects confirmed AI `create_asset` and `create_liability` actions to a transaction-scoped Balance Mutation Service. The existing proposal-level `CONFIRM_AI_PROPOSAL` coordinator remains the only idempotency and PostgreSQL transaction boundary. Ordinary Asset/Liability HTTP CRUD, balance queries, valuation, currency conversion, and external infrastructure are explicitly out of scope.

## Acceptance contract

- A member/admin can confirm a server-owned Asset or Liability proposal only after the proposal item type and edited action type match.
- The balance fact, proposal claim/completion, item result, AuditEvent, and IdempotencyRecord commit atomically.
- Same-key confirmation replays the stored result without a second balance fact.
- Viewer, non-member, malformed/tampered, expired, and transaction-failure paths leave balance tables and proposal state unchanged.
- Asset `value` and Liability `amount` are finite non-negative values; currency is normalized to a three-letter uppercase code.
