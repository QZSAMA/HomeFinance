## 实施结果

普通 Liability 的 POST/PUT/DELETE 已统一进入：

```text
authMiddleware
  → requireFamilyAccess / requireFamilyWriteAccess
  → Liability HTTP adapter
  → balanceMutationService
  → FinancialMutationCoordinator
  → transaction-scoped Prisma adapter
  → Liability + AuditEvent + IdempotencyRecord
  → Family.cacheVersion trigger
```

- GET 使用集中式 `requireFamilyAccess`，列表和分页响应保持兼容。
- POST 使用 `CREATE_LIABILITY`；PUT/DELETE 分别使用 `UPDATE_LIABILITY`、`DELETE_LIABILITY`。
- 更新和删除均以 `id + familyId + version` 做 CAS；更新成功后版本从 1 递增到 2，过期版本返回 `VERSION_CONFLICT`。
- 所有 mutation 使用 scope 为 `familyId + actorScope + operation + key` 的幂等记录，并在同一事务内写审计和结果；成功写入由数据库 trigger 推进 `Family.cacheVersion`。
- route 中没有直接 `prisma.liability.create/update/delete`，没有 route-local `checkFamilyAccess`。
- Liability 估值、跨币种换算、Balance query、软删除和 AI proposal 语义不属于本切片。

## PostgreSQL 验收场景

在 `localhost:5433/homefinance_phase1_test` 的 PostgreSQL 18.1 上验证：

- 20 路同 key create 只提交 1 条 Liability、1 条 IdempotencyRecord、1 条 Liability AuditEvent，其他 19 路 replay；`Family.cacheVersion` 只增加 1 次。
- 同 key 不同 payload 返回 `409 IDEMPOTENCY_KEY_REUSED`，Liability、幂等、审计和 family revision 均不变化。
- 成功 update 将 `version` 从 1 变为 2；旧版本 update/delete 均返回 `409 VERSION_CONFLICT` 且零副作用；随后使用版本 2 成功 delete。
- viewer 和非成员在 centralized write middleware 处返回 403，所有 Liability/幂等/审计/revision 计数不变化。
- coordinator executor 返回空白 resourceId 时返回 `VALIDATION_FAILED`，Liability、幂等、审计和 revision 全部回滚。
- 本次只执行了既有非生产数据库的增量 migration deploy；fresh-schema rehearsal 尚未单独记录，不能把它作为本卡证据。
