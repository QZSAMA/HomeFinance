# 家庭选择跨刷新保持设计

## 背景

浏览器 E2E 的家庭隔离旅程在创建第二个家庭后失败。创建接口返回了家庭 B，创建完成时页面也短暂选择了 B；但跳转到交易页使用完整浏览器刷新后，Zustand 内存状态被重置，`FamilySelector` 默认选择家庭列表第一项 A。交易页因此继续显示家庭 A 的交易，用户选择意图没有被保持。

## 目标与非目标

目标：

- 当前家庭选择在应用内路由跳转和完整页面刷新后保持。
- 只恢复当前登录用户可访问的家庭；本地值不能绕过任何后端 family membership 授权。
- 创建家庭后继续自动选择新家庭。
- 当持久化的家庭已被删除、退出成员资格或数据损坏时，安全回退到返回列表中的第一个家庭；没有家庭时保持空选择。
- 登出时清理当前家庭选择，避免同一浏览器后续登录者继承旧租户上下文。

非目标：

- 不把家庭对象、交易或财务数据持久化到浏览器。
- 不改变后端家庭授权、家庭时区不可变或交易查询契约。
- 不新增 URL 家庭参数或服务端用户偏好表。

## 方案

采用浏览器 `localStorage` 仅保存当前家庭 ID。`FamilySelector` 加载服务端家庭列表后按以下顺序选择：

1. 若列表包含持久化 ID，使用该列表中的完整家庭对象。
2. 否则若内存中已有且仍在列表中的当前家庭，使用列表中的同 ID 对象。
3. 否则选择列表第一项。
4. 列表为空则清理持久化 ID 并保持空选择。

`setCurrentFamily` 在选择变更时立即写入 ID；传入 `null` 时移除 ID。登录用户的家庭列表仍是唯一可信来源，服务端请求在恢复选择前完成。为避免旧请求覆盖新选择，加载回调只在组件仍挂载时应用列表，并再次从 store 读取当前选择；若用户已在请求期间手动选择家庭，则不覆盖该选择。创建家庭沿用现有 `setCurrentFamily(newFamily)`，因此会同步更新内存和持久化 ID。

登出流程在移除认证凭据的同时移除当前家庭 ID。异常的 `localStorage` 读写按不可用存储处理，不阻断家庭列表加载。

## 组件与数据流

- `useFamilyStore`：集中封装当前家庭 ID 的存取和清理，避免页面直接操作存储键。
- `FamilySelector`：负责服务端列表加载、恢复/回退选择和列表对象同步；不再在组件外复制恢复逻辑。
- `FamiliesPage`：创建成功后更新列表并调用统一的 store 选择动作。
- `useAuthStore`：登出时调用 store 清理动作（或导出无 React 依赖的清理函数）。

数据流：

```text
用户选择/创建家庭
        │
        ▼
useFamilyStore.setCurrentFamily
        ├── 更新 Zustand 内存
        └── 写入 currentFamilyId

完整刷新
        │
        ▼
FamilySelector 请求 /families
        │
        ├── 持久化 ID 属于返回列表 → 恢复该家庭
        ├── ID 无效 → 选择首个家庭并覆盖持久化值
        └── 空列表 → 清理持久化值并保持 null
```

## 错误处理与安全边界

- `localStorage` 的值只作为候选 ID；任何交易、报表、文件或 AI 请求仍使用服务端验证过的 `currentFamily.id`。
- 持久化值不是 JSON 家庭对象，不会携带过期成员、角色或财务数据。
- 解析失败、写入被浏览器拒绝或列表请求失败时不抛出新的 UI 错误；保持现有加载/错误表现，并让当前内存状态继续生效。
- 当当前家庭不再出现在服务端列表中，必须先清理旧 ID，再选择合法列表项，避免失效值反复恢复。
