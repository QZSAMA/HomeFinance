# V3.3 资产追踪增强 - 设计文档

> 日期：2026-07-23
> 分支：feature/v3-development
> 前置：V3.2 已完成（多币种、汇率服务已就绪）

## 现状分析

当前资产追踪的关键缺陷：
1. **资产价值静态**：Asset.value 由用户手动录入，无自动刷新
2. **无行情数据**：项目中没有任何 quote/market/valuation 代码
3. **无净值历史**：资产负债表只返回当前快照，无时间序列
4. **分红靠字符串匹配**：Income.category 通过 `includes('利息')` 识别，无结构化分类

## 目标

让资产价值"活起来"——自动获取股票/基金行情，记录净值变化轨迹，结构化投资收益。

## 子任务

### V3.3.1 行情 API 服务（股票/基金实时估值）

**问题**：Asset.value 是静态的，股票/基金价格变动后需手动更新。

**方案**：

#### 数据模型变更

Asset 新增字段：
```prisma
model Asset {
  // ... 现有字段
  symbol      String?  // 股票/基金代码，如 "600519" / "000001.SZ" / "AAPL"
  quantity    Decimal? @db.Decimal(15, 4)  // 持有数量
  marketPrice Decimal? @db.Decimal(15, 4)  // 最新行情价格（缓存）
  marketPriceDate DateTime?  // 行情更新时间
  unit        String?  // 单位："股" / "份" / "克"
}
```

新增 MarketData 表（行情缓存）：
```prisma
model MarketData {
  id        String   @id @default(cuid())
  symbol    String   // 证券代码
  name      String?  // 证券名称
  price     Decimal  @db.Decimal(15, 4)
  change    Decimal? @db.Decimal(15, 4)  // 涨跌额
  changePercent Decimal? @db.Decimal(10, 4)  // 涨跌幅
  source    String   // "sina" | "eastmoney" | "manual"
  date      DateTime @default(now())

  @@unique([symbol, date])
  @@index([symbol])
}
```

#### 行情服务

创建 `backend/src/services/marketDataService.ts`：
- `getQuote(symbol: string): Promise<{ symbol: string; name: string; price: number; change?: number; changePercent?: number }>`
  - 优先查 MarketData 表缓存（当日）
  - 缓存未命中时调用外部 API
  - **免费数据源**：新浪财经 API（`https://hq.sinajs.cn/list={symbol}`）
    - A 股：`sh600519` / `sz000001`
    - 港股：`hk00700`
    - 美股：`gb_aapl`
  - 解析返回的实时行情数据
  - 成功后写入 MarketData 表
  - API 失败时降级查历史缓存
- `getQuotes(symbols: string[]): Promise<MarketQuote[]>` 批量获取
- `refreshAssetPrice(assetId: string): Promise<void>`
  - 读取 Asset.symbol
  - 调用 getQuote
  - 更新 Asset.marketPrice 和 marketPriceDate
  - 如果有 quantity，计算 value = marketPrice * quantity
- `refreshAllAssetPrices(familyId: string): Promise<{ updated: number; failed: number }>`
  - 查询所有有 symbol 的 Asset
  - 批量调用 getQuotes
  - 逐个更新 marketPrice

#### 行情路由

创建 `backend/src/routes/marketData.ts`：
- `GET /quote?symbol=600519` - 获取单个行情
- `POST /refresh` - 刷新家庭所有资产行情（需要 auth + 家庭权限）
- `POST /refresh/:assetId` - 刷新单个资产行情
- 挂载到 `/api/families/:familyId/market-data`

#### 资产路由改造

修改 `backend/src/routes/assets.ts`：
- 创建/更新资产时支持 symbol、quantity、unit 字段
- GET 列表返回 marketPrice 和 marketPriceDate
- GET `/allocation` 端点优先使用 marketPrice * quantity 计算 value（如果有 symbol）

**测试**：
- 单元：marketDataService 缓存命中/未命中、API 失败降级、refreshAssetPrice 更新逻辑
- 单元：getQuotes 批量请求
- 集成：GET /quote 返回行情数据
- 集成：POST /refresh 刷新资产价格
- 集成：创建资产带 symbol/quantity 字段

### V3.3.2 净值历史追踪

**问题**：只有当前快照，无法看到净值变化趋势。

**方案**：

#### 数据模型

新增 NetWorthHistory 表：
```prisma
model NetWorthHistory {
  id          String   @id @default(cuid())
  familyId    String
  family      Family   @relation(fields: [familyId], references: [id], onDelete: Cascade)
  date        DateTime @db.Date  // 日期精度，每天一条
  totalAssets Decimal  @db.Decimal(15, 2)
  totalLiabilities Decimal @db.Decimal(15, 2)
  netWorth    Decimal  @db.Decimal(15, 2)
  assetBreakdown Json  // { STOCK: 1000, CASH: 500, ... }
  createdAt   DateTime @default(now())

  @@unique([familyId, date])
  @@index([familyId, date])
}
```

#### 净值快照服务

创建 `backend/src/services/netWorthService.ts`：
- `takeSnapshot(familyId: string): Promise<NetWorthSnapshot>`
  - 查询所有 Asset（用 marketPrice * quantity 或 value）
  - 查询所有 Liability
  - 汇总 totalAssets / totalLiabilities / netWorth
  - 按 type 聚合 assetBreakdown
  - 写入 NetWorthHistory（upsert，当日唯一）
- `getHistory(familyId: string, startDate: Date, endDate: Date): Promise<NetWorthHistory[]>`
- `getLatestSnapshot(familyId: string): Promise<NetWorthSnapshot | null>`

#### 定时快照

在 `backend/src/jobs/scheduler.ts` 新增定时任务：
- 每日凌晨 0:30 执行 `syncAllFamiliesNetWorth()`
- 遍历所有 Family，调用 takeSnapshot
- 通过 `ENABLE_SCHEDULER` 控制

#### 净值历史路由

创建 `backend/src/routes/netWorth.ts`：
- `GET /history?startDate=&endDate=` - 获取净值历史
- `POST /snapshot` - 手动触发快照
- 挂载到 `/api/families/:familyId/net-worth`

#### 报表改造

修改 `backend/src/routes/reports.ts` 的 balance-sheet 端点：
- 优先使用 Asset.marketPrice * quantity（如果有 symbol）计算 value
- 多币种资产调用 V3.2.2 的 `convertToCNY` 换算
- 响应增加 `valuationMethod` 字段（"market" / "manual"）

**测试**：
- 单元：takeSnapshot 正确汇总
- 单元：getHistory 返回时间序列
- 单元：scheduler 定时快照
- 集成：GET /history 返回历史数据
- 集成：POST /snapshot 创建快照

### V3.3.3 投资收益结构化

**问题**：分红/利息靠 `category.includes('利息')` 字符串匹配。

**方案**：

#### Income 模型扩展

```prisma
model Income {
  // ... 现有字段
  incomeType  String?  // "SALARY" | "INVESTMENT" | "DIVIDEND" | "INTEREST" | "RENT" | "OTHER"
  assetId     String?  // 关联的资产（如某股票的分红）
  asset       Asset?   @relation(fields: [assetId], references: [id], onDelete: SetNull)
}
```

Asset 模型新增反向关系：`incomes Income[]`

#### 收益分类服务

创建 `backend/src/services/incomeClassifier.ts`：
- `classifyIncome(category: string, description?: string): string`
  - 匹配关键词映射到 incomeType
  - '工资|薪水' → SALARY
  - '分红|股息|派息' → DIVIDEND
  - '利息|理财收益' → INTEREST
  - '租金|出租' → RENT
  - '投资' → INVESTMENT
  - 其他 → OTHER
- `migrateExistingIncomes(): Promise<void>` 迁移现有 Income 记录（根据 category 自动填充 incomeType）

#### 路由改造

修改 `backend/src/routes/incomes.ts`：
- 创建/更新时支持 incomeType 和 assetId 字段
- GET 列表支持 `?incomeType=DIVIDEND` 筛选

修改 `backend/src/routes/reports.ts` 的 cash-flow 端点：
- 用 incomeType 替代字符串匹配
- 向下兼容：无 incomeType 的记录用 classifyIncome 回退

**测试**：
- 单元：classifyIncome 各关键词映射
- 单元：migrateExistingIncomes 批量迁移
- 集成：创建 Income 带 incomeType 和 assetId
- 集成：GET incomes 筛选 incomeType
- 集成：cash-flow 报表用 incomeType 分类

## 风险

1. **新浪 API 稳定性**：免费接口可能限流或不稳定，需降级策略（历史缓存 + 手动录入）
2. **海外股票**：新浪支持美股/港股，但格式不同，需适配
3. **净值快照幂等**：同一天多次执行应 upsert，不重复创建
4. **Income 迁移**：现有 Income 无 incomeType，需后台迁移脚本
5. **行情刷新频率**：免费 API 有请求限制，批量刷新需控制并发

## 非目标（明确不做）

- 不做实时 WebSocket 行情推送（复杂度高，HTTP 轮询足够）
- 不做技术分析图表（K 线、MACD 等，超出范围）
- 不做多券商对接（需券商授权）
