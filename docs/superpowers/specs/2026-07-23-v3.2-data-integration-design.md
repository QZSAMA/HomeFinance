### V3.2.1 银行账单格式扩展

**问题**：当前只支持 alipay/wechat 两种 CSV 格式，常见银行账单无法导入。

**方案**：在 `backend/src/services/importService.ts` 增加解析器：
- 招商银行（CMB）：列含 `交易日期`, `交易金额`, `交易摘要`, `交易类型`（`支`/`收`）
- 工商银行（ICBC）：列含 `交易日期`, `交易额`, `摘要`, `对方账户`
- 中国银行（BOC）：列含 `交易日期`, `交易金额`, `记账币种`, `摘要`

`VALID_FORMATS` 扩展为 `['alipay', 'wechat', 'cmb', 'icbc', 'boc']`。

**测试**：
- 单元：各银行 CSV 字符串解析为正确的 `ImportedTransaction[]`
- 集成：`POST /api/families/:id/import/csv` 上传各格式 CSV 返回预览
- 现有 alipay/wechat 测试保持通过

### V3.2.2 多币种支持（汇率换算）

**问题**：Asset/Liability 已有 `currency` 字段但无汇率换算，报表只按原值汇总。

**方案**：

#### 数据模型变更

新增 `ExchangeRate` 表（缓存汇率避免重复请求）：
```prisma
model ExchangeRate {
  id        String   @id @default(cuid())
  from      String   // 源货币，如 "USD"
  to        String   // 目标货币，如 "CNY"
  rate      Decimal  @db.Decimal(15, 6)
  date      DateTime @default(now())
  source    String   // "manual" | "exchangerate-api" | "fixer"

  @@unique([from, to, date])
  @@index([from, to])
}
```

#### 汇率服务

创建 `backend/src/services/exchangeRateService.ts`：
- `getRate(from: string, to: string, date?: Date): Promise<number>`
  - 优先查数据库缓存（当日）
  - 缓存未命中时调用外部 API（默认 exchangerate-api.com 免费层）
  - API 不可用时降级：返回 1（同币种）或抛错（跨币种无缓存）
  - 每日只请求一次，结果入库
- `convertToCNY(amount: number, from: string, date?: Date): Promise<number>`
- `getSupportedCurrencies(): string[]` 返回支持的货币列表
- 环境变量 `EXCHANGE_RATE_API_KEY`（可选，免费层不需要）

#### 报表改造

修改 `backend/src/routes/reports.ts`：
- 报表查询时对非 CNY 资产/负债调用 `convertToCNY` 换算
- 响应增加 `originalCurrency` 和 `exchangeRate` 字段
- 支持查询参数 `?currency=CNY` 指定目标币种

**测试**：
- 单元：exchangeRateService 缓存命中/未命中、API 失败降级
- 单元：convertToCNY 同币种返回原值
- 集成：报表返回多币种资产换算后的合计

### V3.2.3 账单同步配置（定时任务框架）

**问题**：用户需手动上传 CSV，无法定期自动同步。

**方案**：

#### 数据模型变更

新增 `ImportSource` 表（存储同步配置）：
```prisma
model ImportSource {
  id            String   @id @default(cuid())
  familyId      String
  name          String   // "支付宝主账号"
  type          String   // "alipay" | "wechat" | "cmb" | ...
  config        Json     // 加密存储的配置（如邮箱、文件路径模式）
  lastSyncAt    DateTime?
  lastSyncStatus String? // "success" | "failed"
  lastSyncError  String?
  isActive      Boolean  @default(true)
  createdBy     String
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  @@index([familyId])
}
```

#### 同步服务

创建 `backend/src/services/syncService.ts`：
- `syncImportSource(sourceId: string): Promise<{ success: boolean; imported: number; error?: string }>`
- 实现策略：**本地文件目录监听**（更安全，不存凭证）
  - 用户将银行/支付宝导出的 CSV 放到指定目录（如 `./imports/{familyId}/`）
  - 系统定期扫描目录，匹配 `ImportSource` 配置
  - 解析后调用现有 `parseCSV` + 批量创建
  - 成功后移动文件到 `./imports/{familyId}/archived/`

#### 定时任务

创建 `backend/src/jobs/scheduler.ts`：
- 使用 `node-cron`（新依赖）
- 每日凌晨 2:00 扫描所有 `isActive` 的 ImportSource
- 调用 `syncImportSource`
- 更新 `lastSyncAt` / `lastSyncStatus`
- 在 `app.ts` 启动时初始化调度器（可通过 `ENABLE_SCHEDULER=false` 禁用）

**测试**：
- 单元：syncImportSource 成功解析并导入
- 单元：目录不存在时降级
- 单元：scheduler 初始化和停止
- 集成：创建 ImportSource → 触发同步 → 验证数据导入

## 风险

1. **汇率 API**：exchangerate-api.com 免费层有请求限制（每月 1500 次），但每日只请求一次，足够
2. **银行 CSV 格式变化**：银行可能调整导出格式，解析器需容错（未知列时降级）
3. **定时任务单例**：多实例部署时需防止重复执行（可用 Redis 分布式锁，本期暂不处理）
4. **凭证安全**：ImportSource.config 存储敏感信息，需加密（本期用 JSON 占位，标注 TODO 加密）

## 非目标（明确不做）

- 不做银行 API 直连（需要银行授权，超出范围）
- 不做支付宝/微信 OAuth 登录同步（涉及第三方授权，复杂度高）
- 不做多实例分布式锁（V3.2 单实例足够）
