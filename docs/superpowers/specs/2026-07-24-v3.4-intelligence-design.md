# V3.4 智能化与自动化 - 设计文档

> 日期：2026-07-24
> 分支：feature/v3-development
> 前置：V3.3 已完成（行情、净值历史、投资收益结构化已就绪）

## 现状分析

现有 AI 能力边界（基于代码探索）：
1. **Action 类型不全**：aiActions.ts 只有 create/delete/query，无 update_*（无法自然语言修改记录）
2. **无异常检测**：项目中没有任何 anomaly 相关代码，大额支出、频率突变无感知
3. **无预算告警**：budgets 只有 /progress 返回百分比，无后端推送、无定时扫描
4. **AI 日志不完整**：/analyze 漏埋点，tokenUsage/model 未记录
5. **分类靠正则**：parseLocalActions 是关键词匹配，无用户历史个性化

## 目标

让系统"主动发现问题"——异常检测、预算告警、AI 记账能力补全。

## 子任务

### V3.4.1 异常检测服务

**问题**：大额支出、消费频率突变、品类异常无任何感知。

**方案**：

#### 检测规则（纯统计，不用 AI，避免成本）

创建 `backend/src/services/anomalyService.ts`：

- `detectAnomalies(familyId: string): Promise<Anomaly[]>`
  - 检测规则 1 **大额支出**：单笔支出 > 该家庭近 90 天支出均值的 3 倍（且 > 500 元）
  - 检测规则 2 **频率异常**：某品类当日支出次数 > 近 90 天日均次数的 5 倍（且 >= 5 次）
  - 检测规则 3 **品类突变**：某品类本月支出 > 上月同品类支出的 3 倍（且 > 1000 元）
  - 检测规则 4 **重复扣款**：同金额同描述 7 天内出现 >= 2 次（复用现有 check-duplicate 逻辑）
  - 返回结构化 Anomaly 列表：
    ```typescript
    interface Anomaly {
      type: 'LARGE_EXPENSE' | 'FREQUENCY_SPIKE' | 'CATEGORY_SURGE' | 'DUPLICATE';
      severity: 'HIGH' | 'MEDIUM' | 'LOW';
      title: string;        // "发现大额支出"
      description: string;  // 详细描述
      amount?: number;      // 涉及金额
      expenseId?: string;   // 关联记录
      category?: string;
      detectedAt: Date;
    }
    ```

- `detectAnomaliesForAll(): Promise<{ total: number; found: number }>`
  - 遍历所有 Family 执行检测

#### AnomalyAlert 持久化（可选存储）

新增 AnomalyAlert 表：
```prisma
model AnomalyAlert {
  id        String   @id @default(cuid())
  familyId  String
  family    Family   @relation(fields: [familyId], references: [id], onDelete: Cascade)
  type      String   // LARGE_EXPENSE | FREQUENCY_SPIKE | CATEGORY_SURGE | DUPLICATE
  severity  String   // HIGH | MEDIUM | LOW
  title     String
  description String
  amount    Decimal? @db.Decimal(15, 2)
  expenseId String?
  category  String?
  isRead    Boolean  @default(false)
  createdAt DateTime @default(now())

  @@index([familyId, isRead])
  @@index([familyId, createdAt])
}
```

- 检测到异常时写入 AnomalyAlert（同 expenseId + type 24 小时内去重）
- 用户可标记已读

#### 路由

创建 `backend/src/routes/anomalies.ts`：
- `GET /` - 获取家庭异常告警列表（支持 ?isRead=false 筛选未读）
- `GET /detect` - 手动触发检测（返回新检测到的异常）
- `PUT /:id/read` - 标记已读
- `PUT /read-all` - 全部标记已读
- 挂载到 `/api/families/:familyId/anomalies`

#### 定时任务

scheduler.ts 新增：每日 8:00 执行 `detectAnomaliesForAll()`（cron: `0 8 * * *`）

**测试**：
- 单元：4 种检测规则各自触发/不触发
- 单元：去重逻辑（24 小时内同 expenseId + type 不重复）
- 单元：detectAnomaliesForAll 汇总
- 集成：GET / 返回告警、PUT /:id/read 标记已读、鉴权

### V3.4.2 预算告警系统

**问题**：预算只有 /progress 百分比展示，无主动提醒。

**方案**：

#### 预算告警服务

创建 `backend/src/services/budgetAlertService.ts`：

- `checkBudgetAlerts(familyId: string): Promise<BudgetAlert[]>`
  - 查询家庭所有有效预算
  - 计算每个预算的当前进度（复用 budgets /progress 逻辑）
  - 规则：
    - 进度 >= 100%：severity HIGH，"预算已超支"
    - 进度 >= 80% 且 < 100%：severity MEDIUM，"预算接近上限"
  - 返回 `BudgetAlert[]`：
    ```typescript
    interface BudgetAlert {
      budgetId: string;
      category: string;
      amount: number;       // 预算金额
      spent: number;        // 已支出
      percentage: number;
      severity: 'HIGH' | 'MEDIUM';
      message: string;
    }
    ```

- `checkBudgetAlertsForAll(): Promise<{ total: number; alerted: number }>`
  - 遍历所有 Family

- 持久化到 AnomalyAlert 表（V3.4.1 的表，type='BUDGET_EXCEEDED' / 'BUDGET_WARNING'）
  - 同一预算同一周期内只告警一次（去重：budgetId + type + 当前周期起始日）

#### 定时任务

scheduler.ts 新增：每日 9:00 执行 `checkBudgetAlertsForAll()`（cron: `0 9 * * *`）

#### 路由

修改 `backend/src/routes/anomalies.ts`（合并告警中心）或扩展 budgets.ts：
- 预算告警合并进异常告警中心（统一在 /anomalies 返回，type 区分）
- `GET /api/families/:familyId/budgets/alerts` - 仅获取预算告警

**测试**：
- 单元：进度 >= 100% 产生 HIGH 告警
- 单元：进度 80-100% 产生 MEDIUM 告警
- 单元：进度 < 80% 不产生告警
- 单元：同预算同周期去重
- 集成：GET /alerts 返回预算告警

### V3.4.3 AI Action 增强 + 日志补全

**问题**：AI 无法修改记录；/analyze 漏埋点；tokenUsage/model 未记录。

**方案**：

#### 新增 update_* Action 类型

修改 `backend/src/services/aiActions.ts`：
- ActionType 扩展：`update_income` | `update_expense` | `update_asset` | `update_liability`
- 每个 update case：
  - 参数：`{ id, ...fields }`（id 必填，其他字段可选）
  - 校验记录存在且属于该 familyId
  - 只更新传入的字段（Zod partial 校验）
  - 返回更新后的记录

#### AI Prompt 更新

修改 `backend/src/services/aiService.ts` 的 ACTION_SYSTEM_PROMPT：
- 增加 update_* 类型说明和 data 格式
- 增加示例："把昨天的餐饮支出改成 100 元" → `update_expense { id, amount: 100 }`
- 查询类 action 支持返回 id（供后续 update 引用）

#### AI 日志补全

修改 `backend/src/routes/ai.ts`：
- /analyze 端点补 logAICall（type='analyze'）
- 所有 logAICall 调用传入 model
- aiService.ts 的 callChatAPI 返回 tokenUsage（从 API 响应 `usage.total_tokens` 解析）
- callChatAPI 签名改为返回 `{ content, tokenUsage }`（或抛错），调用方透传记录

#### 配置化配额（可选增强）

User 表新增 `aiQuotaOverride Int?`：
- aiQuota.ts 中间件读取用户 override，无则用全局 AI_DAILY_QUOTA

**测试**：
- 单元：update_income 修改金额成功
- 单元：update_expense 部分字段更新（只传 amount 不动 category）
- 单元：update 记录不存在返回错误
- 单元：update 跨家庭记录被拒绝（403 语义）
- 单元：callChatAPI 解析 usage.total_tokens
- 集成：/analyze 记录 AiCallLog
- 集成：aiQuota override 生效

## 风险

1. **异常检测误报**：阈值（3 倍均值、5 倍频率）需保守，标注 severity 让用户自行判断
2. **告警轰炸**：去重逻辑必须严格（24h 同 expenseId+type、同预算同周期一次）
3. **AI update 误操作**：update_* 保持用户确认流程（proposedActions 机制），不自动执行
4. **Prisma 迁移**：AnomalyAlert 新表 + User.aiQuotaOverride 字段需部署时迁移

## 非目标（明确不做）

- 不做机器学习异常检测模型（统计规则够用，避免复杂度）
- 不做邮件/短信推送（站内告警中心足够，通知渠道留 V4）
- 不做 AI 自动记账（保持用户确认，安全性优先）
- 不做按 type 细分配额（单一日配额足够）
